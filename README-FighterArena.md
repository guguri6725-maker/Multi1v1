# Iron Duel — 파이터 1대1 프로토타입

`Assets/Scenes/FighterArena.unity`를 열고 Play를 누릅니다. 기존 `SampleScene` 파일은 유지했고, 공유 후처리 프로필에는 패링 발광용 Bloom을 적용했습니다.

## 시작

- 방장 PC: **CREATE ROOM** → 생성된 방코드를 **COPY**로 복사해서 손님에게 전달합니다.
- 손님 PC: **ROOM CODE**에 전달받은 코드 입력 → **JOIN ROOM**. 두 명이 연결되면 3초 뒤 시작합니다.
- 두 PC 모두 인터넷이 필요합니다. Unity Relay(DTLS)를 사용하므로 IP 입력이나 공유기 포트 포워딩이 필요하지 않습니다. 최대 방장 1명 + 손님 1명입니다.
- 방장이 나가거나 실행을 종료하면 방이 닫힙니다. 다시 만든 방은 새 코드를 공유해야 합니다. **LEAVE / CANCEL**로 접속 중 요청을 취소할 수 있습니다.
- **PRACTICE** 버튼은 오프라인 연습입니다. **HOW TO PLAY**로 조작/연결 안내를 열 수 있습니다.
- **Esc**: 메뉴 열기/닫기. 다시 누르면 게임으로 복귀. **F1**: 마우스 다시 잡기. **R**: 경기가 끝난 후 재경기.

다른 PC에는 `Builds/Windows` 폴더 전체를 복사하고 `IronDuel.exe`를 실행합니다. exe만 복사하면 실행되지 않습니다.

개발용 명령줄: `--arena-room-host`, `--arena-room CODE`, `--arena-profile NAME`(동일 PC 다중 실행 인증 분리). 기존 `--arena-host`, `--arena-client`, `--arena-address 192.168.x.x`는 직접 UDP 진단용입니다. 메뉴는 Relay 방코드를 사용합니다. Unity Cloud 프로젝트의 Authentication/Relay가 활성 상태여야 하며 서비스 사용량은 해당 프로젝트에 집계됩니다.

## 전투

| 입력 | 동작 |
| --- | --- |
| WASD / 마우스 | 이동 / 시점 |
| 스페이스 | 접지 상태에서 점프 |
| 좌클릭 후 놓기 | 왼쪽 베기 → 오른쪽 베기 → 가운데 찌르기 |
| 좌클릭 1.5초 미만 유지 후 놓기 | 일반 공격. 상대에게 차지하다 취소하는 동작이 보임 |
| 좌클릭 1.5초 이상 유지 후 놓기 | E 돌진 거리의 70%만큼 전진하며 강공격. 일반 방어를 뚫음 |
| 풀차지 후 1.5초 더 유지 | 누르기 시작한 시점부터 총 3초에 자동 강공격 |
| 우클릭 유지 | 즉시 방어. 준비 지연 없음 |
| 방어 시작 직후 피격 | 우클릭 후 최초 0.2초가 패링 판정 구간 |
| 패링 직후 좌클릭 | 금빛 잔상을 남기는 수직 내려찍기 반격. 상대는 일반 막기/패링 모두 가능 |
| E | 전방 돌진. 휠윈드 중에도 사용 가능 |
| Q | 주변을 연속 공격하는 휠윈드 |
| 1 | 대검 장착 |
| 2 / 3 → 좌클릭 | 번개 / 벽 수류탄 장착 후 투척. 1로 대검 복귀 |

일반 공격 중에는 공격/방어 입력으로 후딜을 취소할 수 없습니다. 공격 애니메이션이 끝난 후 다음 좌클릭을 누릅니다. 오래 쉬면 1타부터 다시 시작합니다. 강공격은 일반 방어를 깨지만, 타이밍을 맞춘 패링으로 막을 수 있습니다. 뒤쪽 공격은 방어할 수 없습니다.

차지할수록 칼의 위치가 서서히 높아지며 준비 동작이 상대 클라이언트에도 동기화됩니다. 패링에 성공하면 칼이 1.5초 동안 금빛으로 빛나고 불꽃이 퍼집니다. 이 시간 안에 좌클릭하면 반격하며, 내려찍을 때 금빛 궤적이 표시됩니다. 차지 강공격과 반격은 판정이 서로 다른 공격입니다.

수류탄은 포물선으로 날아가 충돌 시 발동합니다. 번개는 범위 내 본인과 상대 모두에게 15 피해와 **6초간 80% 감속**을 줍니다. 둔화는 일반 이동에만 적용되며 강공격 돌진과 E 돌진의 속도·거리는 유지됩니다. 폭발은, 돌벽 뒤로 관통하지 않습니다. 벽 수류탄은 착지 지면에 네 기둥을 만들고 이동·공격·투사체를 막습니다. 벽은 **10초 후 소멸**하고 강공격 또는 패링 반격 한 번에 맞은 기둥이 파괴됩니다. 일반 공격으로는 부서지지 않습니다. 벽 생성 순간 실제로 겹친 플레이어만 가두며, 갇힌 상태에서도 차징과 공격은 가능합니다. 몸에 겹친 기둥을 강공격으로 부수면 다시 이동할 수 있습니다.

1대1 테스트 설정: 종류별 라운드당 **2개**, 공통 쿨다운 **8초**, 번개 피해 **15**, 반경 **4m**, 돌기둥 체력 **100**, 장비 교체 **0.25초**. 이 수치 전체를 원작과 동일하다고 검증한 것은 아닙니다. 둔화율 80%와 지속시간 6초는 현재 사용자 지정 설정입니다. 네 기둥 및 공통 쿨다운 구조는 원작 소모품 가이드를 참고했습니다. 차지/방어/반격 규칙은 사용자가 지정한 변경 사항을 우선 적용했습니다.

현재 테스트 밸런스: 체력 250, 일반 공격 34/34/42, 강공격 65, 정면 일반 방어 80% 감소, 사거리 2.7m, 돌진 쿨다운 12초, 휠윈드 쿨다운 40초 및 26×4+38 피해. 수치는 던전본의 정확한 복원이 아닌 검증용 값입니다.

## 구성과 한계

- 아레나, 두 캐릭터, 대검, HUD는 Unity Hierarchy에 직접 생성했습니다. 참조는 각 컴포넌트의 `Links` Inspector 필드에 연결했습니다.
- 수류탄 표시, 투사체, 네 기둥 돌벽 4세트, 금빛 칼/불꽃/잔상도 Hierarchy에 만들고 연결했습니다. 서버는 미리 만든 오브젝트의 상태를 바꾸어 재사용합니다.
- UI와 아이콘은 Hierarchy에서 제작했습니다. 방코드 복사를 포함한 버튼 OnClick은 Inspector에 영구 연결되어 있으며 런타임 생성/자동 연결 코드는 없습니다. 장비 카드에는 선택 상태, 남은 수량, 공통 쿨다운을 표시합니다. Esc로 메뉴를 열어 장비/스킬 버튼도 클릭할 수 있습니다.
- Unity Netcode for GameObjects 2.13.3 / Unity Transport 사용. 서버가 이동, 명중, 피해, 쿨다운, 승패를 결정합니다. 클라이언트는 자기 슬롯의 입력만 보낼 수 있습니다.
- 원작 에셋을 가져오지 않고 Unity 기본 도형으로 만들었습니다. Blender 연결은 확인했지만 모델링에는 사용하지 않았습니다.
- 캐릭터 명중은 공격의 유효 시점에 거리·방향·벽 가림을 검사합니다. 기본 공격은 검의 세 지점을 물리 틱마다 스윕해 벽 충돌 시 중단합니다. 손님 캐릭터에는 이동·점프·돌진 예측과 서버 입력 확인 후 재생 보정이 적용됩니다. 공격 모션은 즉시 표시하지만 명중·피해·패링의 최종 판정은 서버가 합니다. 아직 과거 위치를 되감는 명중 지연 보상, 정밀 메시 충돌, 전문 캐릭터 애니메이션, 사운드는 없습니다.
- 연습 상대는 전투 판정 확인용입니다. 추적/회피/전술 AI는 없습니다.

## 공격 예고 동작 / 시야 / 시각 피드백

기본 베기 1·2타는 0.4초, 찌르기 3타는 0.46초 동안 칼을 당긴 뒤 공격합니다. 준비 구간에는 피해가 없고, 베기 타격은 0.46초, 찌르기는 0.52초에 발생합니다. 총 동작 길이는 베기 0.9초, 찌르기 0.96초입니다. 세 타수 모두 패링할 수 있습니다.

장애물과 둔화가 없는 경우 E는 4.16m, 강공격 전진은 2.912m입니다. 실제 이동은 벽/캐릭터 충돌과 둔화에 영향을 받습니다. 자기 머리·몸통·팔·다리·신발 9개 렌더러를 숨기고 상대의 몸은 표시합니다. 무기/수류탄은 계속 보입니다. HUD는 자기 HP만 표시합니다.

HIT/BLOCK/PARRY 글자는 제거했습니다. 피격자는 몸이 잠깐 붉게 밝아지고, 일반 막기는 청색 불꽃, 패링은 금빛 효과로 구분합니다. 자기 피격/막기/패링은 화면 가장자리 색으로도 표시합니다. 효과 오브젝트와 가장자리 UI는 Hierarchy에 직접 제작하고 Inspector로 연결했습니다.
이번 변경 검증: `readability-report.json` 27개(3연타 준비/패링, 70% 이동 거리, 몸 숨김, 자기 HP, 점멸/불꽃/화면 가장자리), `combat-report.json` 24개, `revision-report.json` 25개가 통과했습니다. 준비 동작을 보고 패링하는 테스트는 실제 공격 입력과 서버 타격 시점을 사용했습니다.

별도 Windows 클라이언트에서도 자기 몸 숨김, 상대 몸 표시, 상대 피격 점멸, 방어 불꽃, 자기 HP만 표시, 글자 없는 조준점을 확인했습니다. `TestResults/readability-network-report.json` 참조. 커서 잠금에 따라 보이는 자기 화면 가장자리 효과는 Play 모드 검사에서 통과했으며 창 없는 클라이언트에서는 관측되지 않았습니다.

## 공격 중 시점 응답 수정

공격/휠윈드 중 200도/초 회전 제한을 제거했습니다. 카메라와 자기 무기는 매 프레임 로컬 마우스 입력을 즉시 따라가며 서버 회신을 기다리지 않습니다. 서버는 수신한 방향을 해당 물리 틱의 공격 판정보다 먼저 적용합니다. 차징 강공격은 일반 막기로 피해가 감소하지 않고 패링만 가능하며, 패링 후 내려찍기 반격은 기존처럼 막기/패링 모두 가능합니다.

## 벽 접촉 버그 / 점프 / 검 튕김

기존 벽에 나중에 접근한 사람을 감금하던 문제를 수정했습니다. 기존 벽은 이동만 막고 후퇴/옆 이동은 가능하며, 생성 순간 몸에 겹친 사람만 강공격으로 탈출해야 합니다. 스페이스 또는 메뉴의 점프 버튼으로 약 1.25m 점프합니다. 공중 연속 점프와 감금 상태 점프는 불가능합니다.

일반 대검 공격은 준비 동작 뒤 검의 이동 경로를 검사합니다. 돌벽/아레나 벽에 닿으면 청색 불꽃과 함께 검을 회수하고 0.38초간 튕김 후딜이 적용됩니다. 벽 뒤 상대에게 피해를 주지 않으며, 차징 강공격과 패링 강공격은 튕김에서 제외하고 기존 돌벽 파괴 규칙을 유지합니다.
검증: `TestResults/wall-jump-report.json` 27개 통과, 기존 전투 회귀 검사 24개 통과. 벽 접근 후 후퇴/옆 이동, 점프 버튼 Inspector 연결, 점프·착지·공중 재점프 거부, 생성 순간 감금, 3연타 벽 튕김과 강공격 파괴를 포함합니다.
별도 Windows 클라이언트에서 점프 입력, 서버 높이/착지, 벽 충돌 튕김 상태와 불꽃 동기화까지 확인했습니다. `TestResults/wall-jump-network-report.json`. 이번 최종 빌드: 오류 0개, Unity/TMP 셰이더 경고 3개.

## 손님 입력 지연 개선
이동은 물리 틱마다 입력 번호와 함께 전송하고 오래된 패킷을 버립니다. 손님은 로컬 CharacterController로 먼저 움직이고 서버가 확인한 입력 이후만 다시 재생합니다. 일반 공격·차징·강공격·막기·휠윈드 준비 모션도 먼저 표시합니다. 최종 명중과 피해는 방장 권한을 유지합니다. 양쪽 컴퓨터 모두 같은 새 빌드를 사용해야 합니다.
검증: 실제 Relay 위에 양쪽 송신 지연 120ms, 지터 20ms, 송신 손실 1%를 추가했습니다. 측정 RTT 382ms에서 이동·점프·차징·일반 공격·E·강공격이 즉시 반응했고, E 거리 4.160m / 강공격 2.912m, 정지 후 서버 위치 오차는 0.000001m 미만이었습니다. 방향 전환 구간 최대 보정은 0.084m였습니다. 기존 전투 검사 24개도 통과했습니다. 로그: TestResults/prediction-relay-fixed.log. 실제 두 물리 PC의 회선별 체감은 추가 확인이 필요합니다.


### 손님 모션 되감김 수정
